# План доработок macOS-версии Notepad++

Состояние на 2026-09-18: все 579 команд меню реализованы, 639 проверок
встроенного набора проходят, два раунда аудита закрыты (см. `GAPS.md`:
исправлено 35 + 13 ошибок, добавлены резервное копирование по образцу
Windows, обнаружение изменений файла, автоопределение кодировки, аргументы
командной строки, подсветка пользовательских языков, недостающие страницы
настроек). Ниже то, что отделяет порт от Windows-версии для повседневной
работы, в порядке ценности для пользователя. Оценки в рабочих днях одного
разработчика с готовой инфраструктурой сборки и тестов.

Правило для каждой задачи: сначала поведение, затем тест в `app/Tests.mm`,
который падает на старом коде; сверка с исходником Windows в
`PowerEditor/src`, а не с памятью о нём.

## Этап 1. То, что пользователь Windows-версии замечает в первый день (12–16 дней)

### 1.1 Редактор пользовательских языков (UDL) — 4 дня

Keywords Lists, Comment & Number, Operators & Delimiters), стили каждой

## Этап 3. Платформа (8–10 дней)

### 3.1 Локализация — 3 дня
Загрузка `nativeLang.xml` (94 языка в `PowerEditor/installer/nativeLang`):
меню, диалоги, сообщения; выбор языка в настройках; русский как первый
проверяемый.
Файлы: новый `app/Localization.mm`, все места со строками интерфейса
(сейчас захардкожены, `NSLocalizedString` не используется).
Приёмка: `russian.xml` из Windows переводит всё меню без правок.

### 3.2 Обновления, About, Debug Info — 1 день
Проверка новой версии по GitHub Releases с интервалом и настройкой;
использование прокси из настроек; окно About в стиле Notepad++ (лицензия,
ссылки); Debug Info с полным набором полей Windows (путь, командная строка,
режимы, тема, версия ОС, кодовая страница).

### 3.3 Плагины — решение, 2 дня на документ и заглушку
Нативный API плагинов Windows (NPPM_*, NPPN_*, DLL) на macOS невозможен.
Варианты: (а) ничего, встроенные замены (JSON, Compare, XML, FTP, Run,
Function List) считать окончательными; (б) собственный API на
Objective-C-бандлах с подмножеством NPPM_* сообщений; (в) NppExec-подобные
скрипты через Run-консоль. Рекомендация: (в) в первую очередь (скрипты с
переменными `$(…)` и последовательностями команд, как в NppExec), затем
решить по (б). Документировать в `PORTING.md`.

### 3.4 Определение языка по содержимому — 1 день
Модель обучена на 73 языках; для 21 языка примеров нет. Собрать примеры
для оставшихся (из репозиториев Notepad++ и Rosetta), переобучить, поднять
порог единичного ответа по данным. Файлы: `train-language-model.py`,
`resources/language-model.bin`.

### 3.5 Разное — 1 день
Аннотации `nullable` (четыре предупреждения анализатора); удалить
`kNppCP932`-подобные остатки; `outlineView:child:` при отсутствии корня;
сортировка по столбцу для десятичных ключей с табами; «Close All But
Pinned» проверить с перетаскиванием закреплённых вкладок.

## Что не планируется

- Родной API плагинов Windows (DLL) — невозможен на macOS.
- Полное соответствие пиксель в пиксель диалогам Win32: используются
  элементы AppKit с той же структурой и теми же настройками.
- Реестр Windows, `%APPDATA%`, `doLocalConf.xml`: настройки живут в
  `NSUserDefaults` и `~/Library/Application Support/NotepadMac`, что
  описано в `PORTING.md`.
